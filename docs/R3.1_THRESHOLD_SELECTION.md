# R3.1 threshold selection: what the protocol required, what was run, and the deviation

This document is the record of how `varion/thresholds.json` came to hold the values it holds. It is written to be
read with `docs/R3.1_PROTOCOL.md` (the pre-registered protocol, kept unmodified) and
`results/r31/selection.json` (the selection output, kept unmodified).

**Summary.** Applied literally, the protocol's step 6 gives *no switching threshold: use configuration A at every
depth*. The frozen file instead says *use A+B at contig depth >= 67.37x*. The difference comes from the freeze script
(`nindels/scripts/r31/freeze_thresholds.py`), which checked only the global threshold. The frozen A+B rule is therefore
**not protocol-compliant** and must not be described as the outcome of the pre-registered rule. It is also not
supported as a general result (see [Implications](#implications-and-limitations)).

Evidence levels used below: **[verified]** = re-derived from the files in this repository (code, `selection.json`,
git history) when this document was written; **[reported]** = taken from earlier project records that are not part
of this repository and was not re-checked here.

## 1. The protocol (`docs/R3.1_PROTOCOL.md`, committed 2026-10-30 16:55:54 +05:00)

Two indel configurations: **A** (`--genotyper multi`) and **A+B** (A plus the repeat error model, `--str-model`).
The question was whether A+B is reliably better than A above some depth. Selection used HG004 chr20 and chr21 only
(downsampling ladder 10, 15, 20, 25, 30, 40, 50x and native). Steps relevant here:

- Step 3: per local-depth bin, dF1 = F1(A+B) - F1(A), 90 % two-sided block-bootstrap interval (2-Mb blocks, 2000
  resamples, seed 31).
- Step 4: **T_local** = lowest bin lower edge such that that bin and *every higher bin* have point estimate dF1 > 0
  **and** CI lower bound > 0; if no bin qualifies, T_local = infinity.
- Step 5: **T_global** = the same rule over whole-chromosome ladder depths, additionally requiring a positive point
  estimate on both chromosomes; if none qualifies, T_global = infinity.
- Step 6: **"If T_local or T_global is infinity, R3.1 defaults to A (B stays available by manual override) and the
  report says so."**

Amendment 1 (17:04:11; it describes itself as written before any selection result was seen) added PASS-only scoring, the local-depth definition, a
minimum of 300 pooled truth indels per bin, and the test ladder. It states that the PASS-only scoring was checked
beforehand to reproduce earlier numbers and refers to this document for that check. **No record of that check was
found in the repository or in the files used to write this document; it cannot be confirmed or refuted here.**

## 2. What the freeze script does [verified]

`nindels/scripts/r31/freeze_thresholds.py` (commit `43ba7dd`, 2026-10-30 17:14:28) reads `selection.json` and:

- `T_global_ladder_key is None` -> `global_min_depth = None`, status "no depth found at which B reliably helps"
  (auto mode then uses A everywhere);
- `T_local_lower_edge is None` -> only appends the note "no local-depth bin met the rule"; it does **not** change
  `global_min_depth`, `local_min_depth` is merely set to `null`, and the status stays `"selected"` whenever the
  global threshold exists.

So the local half of step 6 is not enforced. In `varion/adaptive.py`, `local_min_depth = null` means "no per-locus
gate" (`gate = thresholds.local_min_depth or 0`), i.e. A+B is applied at every locus of a qualifying contig, which
is the opposite of "infinity".

## 3. What the selection data show [verified from `results/r31/selection.json`, sha256 `a94ad67c...`]

dF1 = F1(A+B) - F1(A) on HG004 chr20 + chr21 pooled, 90 % block-bootstrap interval.

**Local depth (step 4).** `T_local_lower_edge = null`.

| Local depth | truth indels | dF1 | 90 % CI |
|---|---|---|---|
| < 10 | 16,902 | -0.0601 | [-0.0651, -0.0552] |
| 10-15 | 19,680 | -0.0345 | [-0.0386, -0.0308] |
| 15-20 | 19,266 | -0.0160 | [-0.0190, -0.0132] |
| 20-25 | 17,490 | -0.0049 | [-0.0068, -0.0028] |
| 25-30 | 14,635 | -0.0002 | [-0.0021, +0.0017] |
| 30-40 | 21,126 | +0.0007 | [-0.0012, +0.0026] |
| 40-50 | 14,889 | +0.0007 | [-0.0008, +0.0020] |
| 50-70 | 17,410 | +0.00001 | [-0.0012, +0.0012] |
| >= 70 | 6,698 | **-0.0029** | [-0.0043, -0.0015] |

No bin has a CI lower bound above 0, and the highest bin is significantly negative, so the rule cannot be met by any
lower edge: **T_local = infinity**.

**Global (whole-chromosome ladder depth, step 5).** `T_global_ladder_key = "native"` (target 67.37x, recorded in
`selection.json` as the lower of the two chromosomes' native median depths minus 1).

| Ladder | pooled dF1 | 90 % CI | chr20 | chr21 |
|---|---|---|---|---|
| 10x | -0.0455 | [-0.0490, -0.0417] | -0.0486 | -0.0411 |
| 15x | -0.0275 | [-0.0301, -0.0249] | -0.0297 | -0.0244 |
| 20x | -0.0183 | [-0.0203, -0.0162] | -0.0185 | -0.0180 |
| 25x | -0.0098 | [-0.0119, -0.0079] | -0.0088 | -0.0115 |
| 30x | -0.0040 | [-0.0061, -0.0021] | -0.0045 | -0.0033 |
| 40x | +0.0010 | [-0.0008, +0.0027] | +0.0024 | -0.0011 |
| 50x | +0.0014 | [-0.0002, +0.0030] | +0.0025 | -0.0001 |
| native (67.37x) | **+0.0023** | **[+0.0007, +0.0038]** | +0.0032 | +0.0009 |

Only the top rung satisfies the rule, so **T_global = 67.37x**. This is the highest depth that was tested; nothing
above it was available to show that the effect persists.

**Each chromosome alone** (`selection.json["loco"]`; the key is the chromosome used for selection, and the
script's own comment calls this the leave-one-chromosome-out view): chr20 alone gives T_global = 50x, chr21 alone
gives T_global = infinity (native CI [-0.0013, ...]); both give T_local = infinity. The global threshold is thus not
stable across the two development chromosomes.

## 4. The resulting selection and the deviation

| | Protocol (step 6 applied to the data above) | Frozen `varion/thresholds.json` (commit `2dfd33d`, 2026-10-30 18:25:08 +05:00) |
|---|---|---|
| T_local | infinity | `local_min_depth: null` (read by the code as "no gate") |
| T_global | 67.37x | `global_min_depth: 67.37` |
| Auto-mode behaviour | **A at every depth** | A below 67.37x, **A+B at >= 67.37x**, no per-locus gate |
| status | n/a | `"selected"` |

The frozen setting is not what the protocol prescribes. The commit message says "rule from protocol"; the
`provenance` string in `thresholds.json` contains the note "no local-depth bin met the rule", so the absence of a
local threshold is visible in the file, but nothing in the file or the commit states that step 6 then requires A.

Timeline from git [verified]: protocol 16:55:54; amendment 1 17:04:11; freeze script 17:14:28; freeze commit
18:25:08 (all 2026-10-30, +05:00). `selection.json` first appears in git in the freeze commit itself (`2dfd33d`),
together with `thresholds.json`, so git alone does not show when the selection finished; earlier project records
[reported, not re-checked] put it about one minute before the freeze, meaning the freeze script (17:14) pre-dates
the result it was applied to. All commits carry the repository owner's git identity.

**What is not known.** Whether the omission of the local check was a conscious choice, an oversight, or a different
reading of step 6 is not recorded in the commits or documents of this repository, and this document draws no
conclusion about it. Earlier project records [reported, not re-checked] describe the chronology in more detail.
No evidence of intent to alter the protocol has been found, and none is claimed.

The thresholds, the freeze script, `selection.json` and the protocol are published **unchanged** so that the
deviation can be inspected. This release does not change `thresholds.json`.

## 5. What was affected

- The development selection (`selection.json`) and the A, B, A+B and baseline configurations themselves are not
  affected: the deviation concerns only how the selection was turned into the auto-mode rule.
- The "adaptive R3.1" arm of the held-out test matrix (`nindels/scripts/r31/run_test_matrix.sh`, config `R31`) was run
  with the frozen rule. It differs from the protocol-compliant rule (A everywhere) exactly at contigs/depths >= 67.37x.
  The test-matrix results are **not part of this release**; any report of the adaptive arm must state that it is not
  the protocol-compliant rule.
- Comparisons of A vs baseline, A vs A+B and A vs bcftools do not depend on the thresholds.

## Implications and limitations

1. **Do not describe the frozen A+B rule as protocol-compliant or as a pre-registered result.** At most it is an
   exploratory rule chosen by a documented, partly non-compliant procedure.
2. The protocol-compliant R3.1 behaviour is `varion indel --mode A`. The default `--mode auto` follows the frozen
   (non-compliant) file.
3. The evidence for any switch is weak: one sample (HG004, 2x250), two chromosomes, a top-rung-only effect of
   +0.0023 F1, a lower bound of +0.0007, instability between the two chromosomes, and a local-depth analysis that
   contradicts the global one (>= 70x local depth is significantly *negative* while the 67x global rung is positive).
   The contradiction is unexplained here.
4. Generalisation to other samples, read lengths and platforms was not established by the selection. Any later test
   or reassessment is a separate analysis and is outside this document.
5. A+B clearly *loses* to A below about 30x in the development data (dF1 down to -0.046 at 10x); that part of the
   selection is consistent across both chromosomes.

## Reproducing the selection

```bash
python3 nindels/scripts/r31/select_threshold.py        # needs the dev runs from run_dev_matrix.sh; writes selection.json
python3 nindels/scripts/r31/freeze_thresholds.py results/r31/selection.json varion/thresholds.json
python3 -m unittest tests_varion/test_selection.py     # unit tests of the rule, binning and bootstrap functions
```

`nindels/scripts/r31/datasets.json` hard-codes machine-specific paths (`/mnt/hdd/...`, `/home/...`); edit them for
your system. The dev runs need the HG004 chr20/chr21 BAMs, GIAB v4.2.1 truth/BED, GRCh38 reference, htslib,
samtools/bcftools and hap.py 0.3.15; they are not included in the repository. Re-running `freeze_thresholds.py`
would rewrite `thresholds.json` (it stamps today's date and the current commit) - do not run it in a release tree
without intending that.
