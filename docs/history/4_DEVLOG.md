## [2026-08-10] — Fix: mock VCF REF alleles were invented, not read from the FASTA

### Гипотеза:
Recall потолок ~0.78, наблюдавшийся во всех прогонах проекта, вызван
не свойством модели, а тем же классом бага, что и предыдущие два
(BAM без CIGAR, vocab_size) — данные, а не обучение.

### Что сделано:
- Найдена причина (диагностировано вчера, 09-08): `generate_mock_vcf.py:21`
  выбирал REF случайно (`random.choice(bases)`), никогда не читая FASTA.
  Подтверждено эмпирически: VCF REF совпадал с FASTA только в
  94/374 = 25.1% локусов. Для SNP это означало, что ALT попадал на
  настоящую референсную букву на chance-уровне (~25%) — 74/374
  SNP-лейблов имели `input_ids == reference_ids` в 100% ридов.
  Фантомные варианты: метка есть, доказательства нет.
  `generate_mock_bam.py` всё это время сплайсил корректно — он
  честно вставлял мусор.
- Исправлено: REF теперь читается из `chr21_slice.fa` на `POS - 1`
  (0-based внутри, 1-based POS на запись — тот же конвеншен, что и
  в рабочем `load_variants`). ALT-логика не менялась. Indel-ветки
  сохранили форму (1-base insertion, 1-base deletion), только
  захардкоженные буквы `'A'`/`'AT'` стали настоящими.
- Позиции с не-ACGT референсом (N) пропускаются — иначе
  `_sanitize_bases` переписал бы N REF в 'A', воссоздав тот же
  evidence-free лейбл под другой причиной. Срез содержит 251,200
  N-баз, поэтому записей стало 5000 → 4747 (только из-за пропуска N,
  не смена плотности/региона/глубины/сплита — они не тронуты).
- `generate_mock_bam.py` не менялся; BAM регенерирован из
  исправленного VCF существующим (уже проверенным) генератором.
- Добавлен регрессионный тест `test_generate_mock_vcf.py` (8 тестов):
  unit-тесты на `make_record` для всех трёх классов, ALT никогда не
  равен REF, пропуск N, end-to-end проверка что REF совпадает с FASTA
  на 100% записей с 0 фантомных SNP.

Не было: тренировочного прогона, изменений гиперпараметров,

новых данных.

### Решение:
Вопрос о сравнимости, оставленный открытым 09-08, решён самим фактом
регенерации данных: **все метрики проекта до этой точки измерены на
неисправных данных и не сравнимы с чем-либо, измеренным начиная с
этого момента.** Это касается потолка recall ~0.78 и обоих архивных
чекпоинтов (`epoch1_halved_snp_weight_0.9246.pt`,
`...seed2_0.9524.pt`, `best_model.pt`) — они не удалены, остаются
историческим артефактом, но baseline'ом больше не являются. Выводы
про halved SNP weight и 2-seed коллапс сделаны на датасете, где ~20%
SNP-лейблов не имели доказательств вообще — эти выводы требуют
переповторения на новых данных, а не переноса как есть.
