# R3.1 experimental protocol (written before any R3.1 experiment was run)

Date: 2026-10-30. Branch `r3.1`, forked from `nindels-test` @ 12c0452. Frozen versions
(`main`, V1/V2/V2.x/R1/R2, tag/branch `nindels-test`) are not modified.

## Question

R3.1 chooses between two indel configurations of the `nindels` caller:

- **A**  = `--genotyper multi` (joint multi-allelic genotyping, no repeat error model)
- **A+B** = A plus `--str-model` (repeat-specific PairHMM gap-open, estimated from the BAM itself)

The switch depends on depth only if A+B is *reliably* better than A above some depth. That is
not established: HG004 chr20 30x favours A (F1 0.9438 vs 0.9397); 67x favours A+B (0.9548 vs
0.9516); HG001 chr19 30x favours A+B (0.9637 vs 0.9609). None has a confidence interval.
The protocol therefore allows the outcome "no depth threshold exists; default = A".

## Data roles (never mixed)

| Role | Data | Used for |
|---|---|---|
| Training | none. A has no fitted parameters; B's table is estimated without labels from the BAM being called (at run time). The `QUAL >= 20` rule and every other constant are inherited unchanged. | - |
| Threshold selection (development) | HG004 (Illumina 2x250) chr20 and chr21, seeded downsampling ladder 10, 15, 20, 25, 30, 40, 50 x and native (~67x) | the only data used to choose switching thresholds |
| Final test | HG001 chr17 (clean), HG007 chr17 and chr19 (clean), HG003 chr8 (clean, if resources allow) | one run each of baseline, A, A+B, adaptive R3.1 after the thresholds are frozen |
| Previously seen | HG001 chr19 | already used once to validate A+B (commit 1dc2ed4); reported, but labelled "not clean" |

Test data are not opened for tuning. If a test run reveals a problem, it is reported and the
thresholds are not changed; any later change needs new, unseen data.

## Local depth (uneven coverage)

Global depth is one number per BAM; real coverage is uneven. R3.1 therefore uses two levels:

1. **Global depth**, estimated from the BAM index by random-window sampling, decides whether the
   repeat error table is estimated at all (a table fitted from too few reads is unreliable and costs time).
2. **Local depth** at each locus (reads used by the joint genotyper, `LocusCall.depth`) decides
   whether that locus uses the repeat-specific gap-open (A+B) or the default (A).

## Threshold selection rule (fixed now)

1. Run A and A+B (ungated) on every selection BAM; score with hap.py (xcmp), GIAB v4.2.1
   confident regions, PASS calls.
2. For every truth record and call, take the local BAM depth at its position. Bin local depth
   (<10, 10-15, 15-20, 20-25, 25-30, 30-40, 40-50, 50-70, >=70).
3. Per bin, pool all selection runs (chr20 + chr21, all ladder depths) and compute
   dF1 = F1(A+B) - F1(A) with TP/FP/FN counted per record in the bin. Confidence interval:
   non-parametric bootstrap over 2-Mb blocks (2000 resamples, seed 31), 90 % two-sided.
4. **T_local** = the lowest bin lower edge such that for that bin and *every* higher bin the
   point estimate dF1 > 0 **and** the CI lower bound > 0. If no bin qualifies, T_local = infinity.
5. **T_global**: the same rule applied to whole-chromosome ladder depths (dF1 per ladder depth,
   block bootstrap), additionally requiring a positive point estimate on both chromosomes.
   If none qualifies, T_global = infinity.
6. If T_local or T_global is infinity, R3.1 defaults to A (B stays available by manual override)
   and the report says so. No other threshold is tried after looking at test data.
7. The selection is also repeated leave-one-chromosome-out (chr20 -> chr21 and chr21 -> chr20)
   to show whether the threshold is stable.

## Final test metrics

Precision, recall, F1, genotype concordance, FP, FN, wall time, CPU time, peak RSS
(`/usr/bin/time`-style, 3 timed repeats at one depth, 1 at others), broken down by sequencing
depth, homopolymers, tandem repeats, insertions vs deletions (length classes) and genotype
(het / hom-alt). Baseline = `nindels` defaults (frozen behaviour); A; A+B; adaptive R3.1.
Confidence intervals by 2-Mb block bootstrap for paired differences.

## Known limits stated in advance

- hap.py xcmp (vcfeval is not installed).
- Illumina short reads only; GRCh38; autosomes subset.
- Depths other than the native one come from `samtools view -s` downsampling.
- Indels longer than the nindels discovery limits are not represented.
- A switch point learned on one sample/platform (HG004 2x250) may not transfer to 2x148 data;
  the test set is the check, and the result is reported either way.

## Amendment 1 (before any selection result was seen)

- **Scoring** uses PASS-only VCFs (`bcftools view -f PASS`) so every hap.py record reflects exactly what a
  user receives. I checked beforehand that this reproduces the earlier "PASS row of the full VCF"
  numbers (see `docs/R3.1_THRESHOLD_SELECTION.md`).
- **Local depth** of a record = number of primary, non-duplicate, MAPQ >= 20 reads overlapping its position
  (`samtools depth`). The engine's per-locus read count (`DP`) is calibrated against it on the dev data
  and `local_min_depth` is expressed in engine `DP` units.
- **Minimum evidence per bin:** a local-depth bin needs >= 300 pooled truth indels; sparser neighbouring
  bins are merged before the rule is applied.
- **Test-set depth ladder** (fixed now, independent of results): 10, 20, 30, 50, 100 x and native, capped
  at the native depth of each BAM.
- **Runtime repeats:** 3 timed repeats of each configuration at one test depth (30x) per sample, 1 elsewhere.
