# nindels precision / genotype diagnosis (before code changes)

Baseline = commit `18a2010` (`--force-reassess`, untrained rule PASS iff GT ≠ 0/0 and QUAL ≥ 20).
Development data = HG004 chr20 (exploratory; all choices below are made on it).
Independent validation = HG001 chr19, a different individual, chromosome, read length
(2×148 vs 2×250) and sequencing run. It is run once after the configuration is frozen.

## Problem 1 — biallelic genotyping in multi-allelic loci (largest)

**Code**
- `bam_scan.cpp:222` — every normalized CIGAR event with ≥ 2 reads becomes its own candidate.
- `bam_scan.cpp:255-256` — reads carrying a *different* indel at the locus become `Other`.
- `likelihood.cpp` `read_likelihoods` (`:195` copies the CIGAR allele) — the PairHMM compares
  every read, `Other` reads included, against exactly two haplotypes, H_ref and H_alt.
- `likelihood.cpp:230-231` — GL(g) = Σ_r ln[(2−g)/2 P(r|H_ref) + g/2 P(r|H_alt)].

**Assumption:** each read was generated by H_ref or by H_alt.

**Why it fails:** at a locus with alleles {ref, −A, −AA}, a read from the −AA haplotype has to
be explained by H_ref or H_−A. It is one gap closer to H_−A, so it votes for −A. Measured at
`chr20:736736`, 30×: allele −A has 14 own reads + **24/24 Other reads voting H_alt**, ref n = 0
→ 1/1, QUAL 741. Allele −AA is also called 1/1 (QUAL 938). Two homozygous calls at the same
position cannot both be true.

The same mechanism:
- produces the 484 FNs at 1/2 sites (56% of all FNs);
- produces the 100 "2/1" FPs and most of the 422 representation FPs called 1/1;
- produces the "pure" FPs with f = 1, NREF = 0, NOTH > 0 (84% of them).

The count model (`engine.cpp:102`, `likelihood.cpp:240`) has the same flaw: f = n_alt / (n_alt +
n_ref) (`evidence.cpp:48`) leaves `Other` reads out of the denominator.

**Correction (Experiment A): joint multi-allelic genotyping on a haplotype set.**
1. Group candidates whose footprints overlap: [pos − 1, pos + max(ref span, repeat span,
   homopolymer length)]. Each group is one locus.
2. Alleles a = 1..K, ranked by supporting reads; K ≤ 5. Haplotypes: H_0 = reference window,
   H_a = window with allele a applied.
3. Per read r and haplotype a: ℓ_ra = ln P(r | H_a) from the banded PairHMM. The read's CIGAR
   is not used for genotyping; the read is assigned by likelihood only.
4. Mapping uncertainty (the read may belong elsewhere in the genome):
   ℓ'_ra = ln[(1 − ε_r) e^{ℓ_ra} + ε_r e^{max_b ℓ_rb}], with ε_r = 10^(−MAPQ/10).
5. Genotype likelihood for every unordered pair (a, b) with 0 ≤ a ≤ b ≤ K:
   GL(a,b) = Σ_r ln[½ e^{ℓ'_ra} + ½ e^{ℓ'_rb}]  (GL(a,a) = Σ_r ℓ'_ra).
6. Posterior P(a,b | D) ∝ GL × prior. Priors: P(0/a) = θ, P(a/a) = θ/2, P(a/b) = θ/10, with
   θ = 10⁻⁴ for every allele. **These priors are arbitrary** and not fitted; the threshold below
   is not tuned.
7. Call G* = argmax. QUAL = −10 log₁₀ P(0/0 | D), which is a posterior, not a likelihood ratio.
   GQ = −10 log₁₀(1 − P(G* | D)). One VCF record per locus carries G*'s alleles (1/2 allowed).

This also corrects the old QUAL (`likelihood.cpp:215`, `engine.cpp:157`). The old value was
ln[L(0/1) + L(1/1)] − ln L(0/0) scaled by 10/ln 10. That is a likelihood ratio with no prior,
not a probability, so "QUAL ≥ 20" had no fixed meaning.

*Allele balance*: the model never uses an allele-fraction cut-off. A 50:50 read split favours 0/1
only because GL(0,a) beats GL(0,0) and GL(a,a) given each read's likelihoods. Reads that
fit both haplotypes equally (e.g. they end inside the repeat) contribute ~0 to every
comparison instead of being forced into "ref" or "alt".

**Expected:**
- Fewer FPs at multi-allelic sites, and 1/2 recall restored.
- Runtime ≈ (K+1)/2 × HMM work per locus, but loci are fewer than candidates.
- RAM slightly higher per locus.

**Risks:**
- Compound haplotypes (two alleles in cis) and nearby SNPs are not modelled.
- K = 5 truncates very polymorphic STRs.
- Loci split across 250-kb chunk edges.

## Problem 2 — one indel error rate in every sequence context (homopolymers / STRs, depth trend)

**Code:** `likelihood.hpp:17` `gap_open_q = 45`; `likelihood.cpp:30` transitions use the same
gap-open probability δ = 10^(−4.5) at every haplotype position.

**Assumption:** a read shows a spurious indel with probability ≈ 3×10⁻⁵ per position,
everywhere.

**Why it fails:** polymerase slippage in an STR of n units occurs in roughly 10⁻³–10⁻¹ of
reads, and it rises steeply with n. Under H_0 a slipped read costs ln δ ≈ −10.4 nats. Under
H_0/a it costs ln ½ ≈ −0.7. Every reference read costs ln ½ under 0/a. So GL(0/a) > GL(0/0)
whenever the slipped fraction s satisfies

  s · (10.4 − 0.7) > (1 − s) · 0.7  ⇒  s > 6.7%,

**regardless of depth**. Any STR whose true slippage rate is above 6.7% becomes a het call. And
because QUAL grows linearly with the number of reads, those calls pass QUAL ≥ 20 more often at
67× than at 30×. That is the measured precision drop (0.833 → 0.768) and the 1,225 HP ≥ 7 FPs.

**Correction (Experiment B): data-estimated STR slippage, as position-specific gap-open.**
1. *Estimate ε(p, u)* — the per-read probability of a whole-unit slippage in an STR of period
   p ∈ 1..6 and u units — from the same BAM, with no truth labels:
   - Sample STR loci from the reference, at most 300 per (p, u) stratum.
   - At each locus k, count n_k reads spanning the STR ± 3 bp and s_k of them carrying an indel
     whose length is a multiple of p inside it.
   - Fit by EM a three-component binomial mixture: s_k ~ Bin(n_k, ε) for hom-ref loci,
     Bin(n_k, ½) for het loci, Bin(n_k, 1 − ε) for hom-alt loci, with mixing weights π.
   - Strata with < 30 loci inherit from (p, u − 1).
2. *Use ε in the PairHMM:* on each haplotype, positions inside an STR (p, u) get gap-open δ_j
   such that the HMM's probability of a one-unit slip on that STR equals ε(p, u). Calibrate
   numerically once per stratum: compute the slip/clean likelihood ratio R(δ₀) on a synthetic
   STR, then set δ_j = δ₀ · [ε / (1 − ε)] / R(δ₀), capped at 0.25. Outside STRs δ stays Q45.

The threshold argument above then compares s with ε(p, u) instead of with 3×10⁻⁵. A het at
50% still wins easily, but STR noise at s ≈ ε no longer does.

**Expected:**
- Large FP reduction in HP / STR; precision should stop falling with depth.
- Recall loss only at low-depth hets in very long STRs (measured).
- Runtime: one estimation pass (~seconds); no change in RAM.

**Risks:**
- ε also absorbs genuine population polymorphism if many sampled loci are truly polymorphic.
  The mixture components handle this.
- Real somatic or mosaic low-fraction variants would be lost; they are out of scope for a
  germline caller.

## Problem 3 — correlated evidence counted as independent (mate overlap, unmarked duplicates)

**Code:**
- `bam_scan.cpp:203` drops only reads flagged `BAM_FDUP`. **None are flagged in these BAMs**
  (`samtools flagstat`: 0 duplicates). An estimated 1.0% of reads share start, strand and mate
  start.
- `bam_scan.cpp` (evidence loop) and `likelihood.cpp` treat each *read* as an independent
  observation.

**Assumption:** reads are independent samples of the haplotypes.

**Why it fails:**
- 85% of pairs have insert size < 500 bp. With 2×250 reads, both mates cover most loci and
  sequence the *same molecule*, so a PCR slippage error appears in both.
- Duplicates repeat the molecule again.
- Σ_r ln P(r|H) therefore counts one molecule's error 2× (or more). That doubles the evidence
  for STR-noise alleles and inflates QUAL.

**Correction (Experiment C): fragment-level evidence.**
- *Duplicates:* group reads by (start, strand, mate start, insert size). Keep the read with the
  smallest name hash. That choice is deterministic, and both mates of a duplicate pair make
  the same choice.
- *Overlapping mates:* at each candidate, if both mates are informative, keep one observation
  per fragment, namely the mate with the higher mean base quality around the event.
  P(fragment | H) := P(chosen mate | H).

This conservative choice discards the second mate's independent *sequencing* errors. It does
so because PCR errors, which dominate STR noise, are shared.

**Expected:**
- QUAL and evidence for noise alleles roughly halved.
- Less depth inflation; small FP reduction.
- Runtime and RAM slightly lower.

**Risks:**
- Lower power for true hets at low depth (fewer observations), so 15× recall must be checked.
