# V2.x Accuracy Optimization — Final Benchmark

Дата: 2026-09-25. Данные: HG002 chr20, 300×, GRCh38, NISTv4.2.1, `chr20_highconf.bed`, hap.py 0.3.15 (xcmp, `--threads 8`) — без изменений.
V1 и V2 (control) не тронуты; замороженные константы (Binomial 7.0, router 5.411872376933351, PB 10.5, Method C ε=0.01), `MAX_READS=48`, SNP-only и протокол — не менялись. Ничего не закоммичено, manuscript не менялся.

## 1. Главный результат

V2 держал F1 = 0.97243, но 2 649 его FP на 91 % сидят **вне** зоны действия роутера/PB (роутер трогает лишь 707 из 56 M локусов): это low-VAF (медиана 0.17) сайты, чьи ALT-риды имеют BQ ≈ 19 против ≈ 36 у настоящих вариантов — фиксированный ε=0.01 Binomial этого не видит. Дешёвый second-stage (логистическая регрессия на Binomial-выходах + read-evidence, считается только на 163 705 кандидатах с k ≥ 3) поднимает **F1 на независимом holdout с 0.97195 до 0.98902 (ΔF1 = +0.01706, 95 % block-CI [+0.01183; +0.02326]), precision 0.9619 → 0.9964, recall 0.9822 → 0.9818**, FP 1 323 → 122; на полном chr20 (инженерный бенчмарк) F1 0.97243 → 0.98927. Цена: +1.0 % CPU-секунд (wall в пределах шума ±5 %), +2.4 MB RAM, PB-вычислений 707 → 33. Локальный контекст (D) и PB как «last-resort» (B) **не добавляют ничего** сверх per-locus модели (ΔF1 vs A+C: −0.0001, CI включает 0). Остаток ошибок — не решающий слой: 90 % оставшихся FN (558 из 620 на holdout) — это truth-SNP, которых нет в кадре V1 (M-1, окна < 64 bp у границ BED) или с k < 3.

## 7. Что дало реальный прирост

Для каждого механизма: WHAT / WHY / HOW / COST / BENEFIT (holdout, Δ vs V2 с 95 % block-CI) / FAILURE MODE.

**A — cheap evidence layer (24 признака из того же pileup).**
WHAT: для кандидата (frame-локус с k ≥ 3) собираются ALT/REF BQ, MAPQ, strand, расстояние до конца рида, NM, soft-clip, уникальные read-starts, low-BQ-dropped и др. (`include/dnav2/features.hpp`). WHY: 84 % FP V2 имеют `alt_bq_mean` ≤ 25.3, а у настоящих вариантов (TP-вызовов V2) так — 3 из ≈ 70 000. HOW: один проход по ридам колонки, целочисленные аккумуляторы; feature-audit (`V2X_FEATURE_COST_AUDIT.csv`): AUC TP-vs-FP среди вызовов V2 — `alt_nm_mean` 0.976 (инверсия), `alt_bq_mean` 0.917, `alt_clip_frac` 0.976 (инверсия). COST: +1.2 % CPU. BENEFIT: **A как один hard-veto (`alt_bq_mean ≤ 25.33`) уже даёт ΔF1 +0.01574 [+0.01043; +0.02185], FP −1 098, FN +2**. FAILURE MODE: порог 25.3 подогнан под BQ-распределение этого прогона (NovaSeq/Novoalign); на другой платформе/BQ-биннинге сдвинется и начнёт резать настоящие варианты.

**B — adaptive read evidence / MAX_READS.**
WHAT: PB на 24/48/64/96/128/всех ридах и «block-consensus» (PB на непересекающихся 48-ридовых блоках hash-порядка, min/median/max), порог 10.5 заморожен. WHY: V2-анализ показал, что решение PB следует за тем, какие 48 ридов выбрал cap. HOW: `PbStore` (2 байта/рид, вычисление лениво). COST: PB на ≤ 707 локусах ≈ 0. BENEFIT: **больше ридов — хуже**: F1 0.97195 (cap 48) → 0.97056 (128) → 0.96957 (все); cap 24 лучше (+0.0006); block-min лучше всех: ΔF1 +0.00164 [+0.00105; +0.00233], FP −117. Причина — LLR растёт с n, а порог 10.5 неявно откалиброван под ~48 ридов; ответ на ключевой вопрос «получить PB-выгоду без сотен ридов?» — **да, и лучше: PB на ≤ 48 ридах, а не на сотнях**. Cap 48 через новый путь воспроизводит V2 побайтно. FAILURE MODE: block-min консервативен (риск FN на высокоглубинных low-VAF истинных вариантах); выбран из 9 вариантов по dev-F1 (множественные сравнения), holdout подтвердил (+0.0016). Поверх C эффект исчезает.

**C — cheap second-stage classifier.**
WHAT: логистическая регрессия (стандартизация, log1p для счётчиков), вход — Binomial/router-выходы (+A/D), обучена **только на dev**, вес/порог в текстовом model-файле, в C++ — скалярное произведение. WHY: фиксированный ε=0.01 Binomial не знает диплоидный VAF-prior (het ≈ 0.5, hom ≈ 1) и BQ. HOW: `include/dnav2/model.hpp`. COST: 163 705 dot-product'ов ≈ 0. BENEFIT: **C на одних Binomial-выходах: ΔF1 +0.01631 [+0.01111; +0.02248], FP −1 170, FN +34 [17; 53]**; A+C: +0.01706 [+0.01183; +0.02326], FP −1 201, FN +14. Semi-family: shallow-tree/GBT (`V2X_C_MODEL_FAMILIES.csv`): tree depth 3–5 dev-OOF 0.9883, GBT-«потолок» 0.9894 против LR 0.9890 — запас над LR ≈ +0.0005, деревья не выбраны по dev. FAILURE MODE: модель кодирует germline-диплоид; на somatic/mosaic/низкий VAF/контаминацию/полиплоидию будет резать реальные варианты (уже здесь: +34 FN у C на holdout vs V2); обучена на одном образце и одной хромосоме.

**D — local context (±2/5/10/25 bp).**
WHAT: число соседних кандидатов, расстояние до ближайшего, локальный mismatch-rate, depth-ratio, homopolymer/dinucleotide/CpG/slippage по референсу. WHY: кластерные mismatch'и как признак ошибочного выравнивания. COST: ≈ 0 (массивы task'а, O(50) чтений на кандидата). BENEFIT: **D как единственный veto (`nc25 ≥ 3`): +0.00377 [+0.00162; +0.00626], но FN +167**; поверх A+C — **ноль**: D1 (±2) 0.98896, D2 (±5) 0.98900, D3 (±10) 0.98899, D4 (±25) 0.98905, ref-context 0.98886 против 0.98902 без контекста (`V2X_D_CONTEXT_WINDOW_ABLATION.csv`). Ответ на главный вопрос D: **локальный контекст не содержит информации, которой нет у per-locus модели.** FAILURE MODE: veto в плотных кластерах режет истинные варианты (FN +167); контекст усечён на границах task'а (детерминированно, 4 из 80 проверенных локусов).

## 8. Что оказалось бесполезным

* **PB на сотнях ридов** (B4/B5/«all»): монотонно хуже при замороженном пороге.
* **PB как last-resort после классификатора** (C2): 0 выгоды, PB ошибается чаще классификатора в неуверенной зоне.
* **Локальный контекст (D)** поверх per-locus модели: ΔF1 −0.0001…0 во всех окнах; C+D vs C на holdout −0.00015 (n.s.).
* **B поверх C** (B+C ≡ C, полоса 0 выбрана по dev); **A+D ≡ A** (D-veto не выбран после A).
* **Деревья/GBT** вместо логистики: без достоверного выигрыша.
* **AVX2** не пробовался: в V2 уже показан нулевой выигрыш, PB-арифметика вообще не горячий путь.
* **Потолок решающего слоя**: 90 % оставшихся FN не кандидаты (`V2X_ERROR_DECOMPOSITION.csv`: holdout FN 620 = 558 не-кандидатов + 38 кандидатов не вызвано + 24 неверный GT Method C). Снять их можно только расширением кадра (M-1) — это смена протокола; **не делалось**.

## 9. Final recommendation

**V2.x A+C**: Binomial → cheap evidence (A) → логистика (C), PB не нужен. Холдаут F1 0.98902, precision 0.99636, recall 0.98178; full chr20 F1 0.98927; +1.0 % CPU; 221 MB; PB 33 локуса. Если нужна максимальная простота (без модели): **A как один veto** — F1 0.98769 (−0.0013 vs A+C, достоверно). **V2.x_ALL (A+B+C+D)** реализован и измерен (holdout 0.98890, PB 36), но не рекомендуется: то же F1 при большей сложности. Перед использованием на другом образце/платформе модель необходимо переобучить: A-порог BQ и VAF-prior — параметры этого набора данных.

Это F1 ≈ 0.989, не «0.997 любой ценой»: DeepVariant/GATK для подгонки не использовались.

## Ограничения (без смягчений)

1. Один образец (HG002), одна хромосома, одно покрытие (300×), одна платформа: holdout — независимые **регионы**, а не независимые образцы; обобщение на другие образцы/глубины/платформы **не проверено**.
2. Тренировка и оценка — только внутри high-confidence BED; трудные области вне BED не оценивались.
3. Кадр V1 (M-1) не менялся; он ограничивает recall ≈ 0.985 для всех моделей, включая V2.
4. Wall-time на этом ПК шумит ±5 % (page-cache); статистически различимы лишь CPU-секунды (+~1 %).
5. Модели без отдельного timing (`n/t`) имеют тот же compute-путь, что измеренные; их runtime не заявляется.
6. Порог классификатора выбран максимизацией dev-F1 (по OOF); в in-sample dev-числах (A+C 0.98950) есть оптимизм, holdout (0.98902) его не подтверждает сильнее ~0.0005.
7. Контекст D усечён на границах task'ов (~131 kb / разрывы BED).
8. Model-файлы применяются к кандидатам k ≥ 3; локусы k < 3 идут по старому V2-пути (в т.ч. 33 PB).
