This Supplementary Information documents the exploratory neural branch referred to in the
Introduction of the main manuscript (``\ldots\ apart from one weak positive (two of three seeds)
on a side branch (Mamba-style models [16]; Supplementary Information)''). No part of this branch
is used by V1, V2 or V2.x, and nothing here changes any result of the main manuscript. Every
number below is copied from a project record named next to it; paths are relative to the
repository root. \emph{Devlog $n$} means \src{History/$n$\_DEVLOG.md}. Reference numbers refer to
the main manuscript's reference list.

\section{S1. Origin: a neural caller on synthetic reads (August 4--10, 2026)}

The project began as a per-base token classifier (\src{model.py}) predicting
Normal/SNP/Insertion/Deletion from a read sequence, the aligned reference, base quality and
depth. The source describes it as a reference-guided bidirectional ``Mamba'' variant caller, but
its own docstring states that the block ``is \textbf{not} a selective state-space model'': it is
a causal gated convolutional approximation in stock PyTorch, with a receptive field bounded by
the convolution kernel. ``Mamba-style'' in the main text refers to this architecture and its
later variants, not to the selective state-space model of [16].

Training and evaluation data were synthetic reads (\src{generate\_mock\_bam.py}) carrying
variants from \src{generate\_mock\_vcf.py}, placed on a slice of the real chr21 reference. Real
HG002 reads were not used in this phase, so it produced no measurement of real-data accuracy.
The records of this phase (devlogs 3--5, \src{History/DEVLOG\_2026-08-08.md}) mainly document
data and evaluation defects:
\begin{itemize}[leftmargin=1.4em,itemsep=1pt]
\item The mock BAM spliced only SNPs, so the indel classes could not be learned, and the
  vocabulary lacked a gap token (devlog 3).
\item A fixed 0.5 decision threshold made one checkpoint score macro-F1 0.0884; the same
  checkpoint scored 0.9095 at threshold 0.9 (\src{History/DEVLOG\_2026-08-08.md}). The apparent
  ``collapse'' was a consequence of the evaluation rule.
\item The mock-VCF generator drew the REF allele at random, so 81 of 374 SNP labels had no read
  evidence, which capped recall at 0.7834 (devlogs 3--4). After the fix the devlog declared all
  earlier metrics non-comparable.
\end{itemize}
Per-seed numerical records for the synthetic-read runs (devlogs 3 and 5 mention two seeds) are
not retained in a form that can be tabulated here, and none are reported.

\section{S3. The Mamba-style side branch: PB-residual on a powered benchmark}

Devlog 9 found that its test region was too small to show a difference (10 PB errors in total).
The PB-residual model was therefore re-evaluated on a larger split, on side branch
\src{worktree-30x-pb-residual} (commit \src{6c31876}, 2026-08-12). The data were HG002
chr21:32--40 Mb at about 15$\times$, divided into 1-Mb blocks: train blocks 0 and 4 (1.89 Mb,
2,544 SNPs), validation blocks 1 and 5 (1.91 Mb, 2,410 SNPs) and test blocks 2, 3, 6 and 7
(3.81 Mb, 5,704 SNPs). This is the same split described under ``Provenance of the constants'' in
the main manuscript. Each arm's decision threshold was chosen on validation, and the test blocks
were scored once. Three training seeds were used: A = 20260811, B = 424242 and C = 13371337. The
paired bootstrap against PB used 10,000 resamples with seed 20260812.

Two of the three seeds have intervals that exclude zero. The third was run as an unconditional
replication check after A and B had been scored, and its interval includes zero. The branch

gain is not a threshold shift. With the PB prior shuffled between loci, the model fell to
F1 0.7077. In seed B, PB had 56 false positives. The model removed 19 of them and added none.

\section{S4. The side branch inside the cascade}

The trained side-branch checkpoints were then tested as a third stage (PB $\rightarrow$ Mamba)
on chr21:31--32 Mb, a region held out from their training (devlog 12). The pre-registered
verdicts were as follows. \textbf{Stage 2 (PB $\rightarrow$ Mamba): NEGATIVE.} Two of the
three checkpoints were significantly harmful ($\Delta$F1 $-$0.018 to $-$0.073), and the third was
null. \textbf{Stage 3 (full cascade):} the best case was $\Delta$F1 +0.0002 with an interval
straddling zero, at a window amplification of 31.7--61.0$\times$. The two-stage
binomial $\rightarrow$ router $\rightarrow$ PB cascade was the Pareto-optimal arm. The same
devlog reports the PB depth-clipping defect above 48$\times$ that was fixed in devlog 13. This Supplement does not
re-examine whether that defect affected the Stage-2/3 numbers. They are reported as recorded.

\section{S5. Why the neural branch is not part of V1, V2 or V2.x}

\begin{enumerate}[leftmargin=1.6em,itemsep=1pt]
\item On real reads, every neural stage apart from the side branch was null or negative against
  a statistical baseline (S2).
\item The side-branch gain was small (+0.0003 to +0.0019 F1), replicated in two of three seeds
  only, and did not survive integration into the cascade on held-out data (S3, S4).
\item The side branch depends on the PB prior (the shuffled-prior control fell to F1 0.7077), so
  it could only be added on top of the statistical caller, not replace it.
\end{enumerate}
V1 was therefore built from the statistical stages alone. \src{cascade.py} still contains a
dormant Mamba stage, but it is not used by any reported result. The supervised component of
V2.x is a logistic regression and is unrelated to this branch (main manuscript).
