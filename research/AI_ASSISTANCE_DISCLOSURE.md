# AI-Assisted Development Disclosure

This project used Claude (Anthropic) extensively during development,
including for the work this specific dossier documents. This disclosure
separates human and AI-assisted contribution as concretely as possible.

## Human contribution

- Defining the research question (can a cheap screening stage + confidence
  router approximate a more expensive caller's accuracy without losing
  detection quality?).
- Setting the absolute constraints under which every experiment in this
  repository was run: frozen thresholds, no retuning against test results,
  no deletion of inconvenient results, mandatory integrity gates before any
  accuracy number is trusted.
- Directing which datasets/samples/regions to pursue next at each stage of
  the project (HG002 -> cross-chromosome -> cross-sample HG003/HG004 ->
  HG005; external caller comparison; genotype-layer investigation).
- Identifying that the original HG005 stress-test result looked wrong
  (near-zero F1) and directing a specific investigation into extraction
  integrity rather than accepting or explaining away the number.
- **Catching an AI audit error mid-task and directing its correction.** An
  earlier pass of this session concluded no C/htslib implementation existed
  in this repository and that a "~65x speedup" claim was unsubstantiated.
  The human identified that this was wrong — a real, previously-validated
  implementation existed in a specific worktree the AI had not checked — and
  directed a full re-audit and integration rather than accepting the AI's
  first conclusion. This is disclosed in detail below and in
  `PIPELINE_INTEGRITY_AUDIT.md`'s correction note precisely because it is a
  case where AI-assisted work was wrong and human oversight caught it,
  which is the kind of thing this disclosure exists to surface, not hide.
- Final authority over what is reported as SUPPORTED vs NOT SUPPORTED in
  `SCIENTIFIC_CLAIMS.md` — the classification rules were set by explicit
  instruction ("never call it clinically validated," "never claim universal
  superiority," etc.), and every classification in that file was produced
  under those rules, not invented independently by the AI.
- Rejecting invalid results: the original HG005 F1=0.0085 result was
  explicitly not accepted as a scientific finding and was investigated to
  its root cause rather than reported as-is.

## AI-assisted contribution (this session, Claude)

- Reading and tracing the extraction pipeline's coordinate-handling code
  across `providers.py`, `pileup_counts.py`, `extract_bench_v12.py`, and
  several `bench_v14`-`v19` scripts to localize the root cause of the HG005
  reference-integrity bug.
- Writing the fix (`pileup_counts.py::load_counts(..., return_positions=True)`
  and the corresponding call-site changes in `extract_bench_v12.py`).
- Writing the regression test suite (`test_hg005_extraction_integrity.py`,
  11 tests) and running the full existing test suite to confirm no
  regression.
- Running the extraction, cascade/Method-C pipeline, and hap.py Docker
  invocations; parsing their output; computing the stratification,
  rescue-analysis, and error-taxonomy statistics reported in this dossier.
- Drafting every document in `research/` (this file included) and every
  report under `experimental/stress_test/HG005_*` and
  `experimental/performance/CHTSLIB_INTEGRATION_REPORT.md` produced in this
  session.
- **Initially misjudging the "~65x C/htslib speedup" claim as
  unsubstantiated**, by checking only one of several relevant developer
  worktrees and generalizing from a genuine null result found there
  (htslib-internal thread scaling) to a false conclusion about the whole
  codebase. When the human pointed to the correct worktree, re-auditing it,
  finding the real C extension and its existing equivalence proof, rebuilding
  it, independently re-verifying bit-exact equivalence on new data, and
  integrating it into production as the default extraction path.

## What was NOT independently, manually written by a human for this session's output

Essentially none of the prose in `research/` or the HG005 fix's code was
typed by a human character-by-character; it was generated by Claude under
direct, detailed human instruction and iterative correction (including a
clarifying question asked and answered mid-task about scope). This
disclosure does not claim otherwise. The scientific judgment calls —
what counts as a valid experiment, what claims are defensible, when to stop
and ask rather than proceed on an uncertain premise — were exercised by
Claude operating under human-specified rules and were subject to human
review and could be, and were, redirected by the human mid-task. The
clearest example: Claude's own audit wrongly concluded no C/htslib
acceleration existed; the human did not accept this and directed a
re-investigation that found the AI's conclusion was based on an incomplete
search, leading to locating, verifying, and integrating a real
implementation. This disclosure treats that correction as informative, not
embarrassing to omit.

## Recommendation for citation / disclosure in any resulting document

Any paper, application, or portfolio piece built from this dossier should
state plainly that code and documentation were produced with substantial
AI assistance (Claude) under human research direction, consistent with this
file, rather than presenting the artifact as unassisted individual work.
